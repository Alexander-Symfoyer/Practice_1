5. ถ้าคิดเป็น Recursion Tree

Merge Sort ปกติ:

                 n
              /     \
            n/2     n/2
           /  \     /  \
         n/4 n/4  n/4 n/4
              ...

แบ่ง 4:

                    n
          ┌─────────┼─────────┬─────────┐
         n/4       n/4       n/4       n/4
       / | \ ...

แบ่ง n/2:

                         n
        ┌────────────────────────────────┐
       2    2    2    2    2    2 ... 2

ชั้นแรกอาจดูเหมือนสุดยอดเลย เพราะ ลงไปถึงขนาด 2 ทันที

แต่ปัญหาคือ:

เราหนีปัญหาไปไม่ได้ เพราะสุดท้ายต้องเอา subproblem ทั้งหมดกลับมา merge ให้เป็น array เดียว

และการ merge หลายระดับทำให้กลับมาเป็น:

O(nlogn)

จำแบบสั้นที่สุด

n = งานที่ทำในแต่ละชั้น (merge)
log n = จำนวนชั้นที่แบ่ง
ดังนั้น n × log n = n log n
